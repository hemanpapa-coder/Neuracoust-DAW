# 믹서·버스를 NDS에서 — SoundGrid 방식 원격 믹서 설계

2026-07-29 확정. 방향 근거: Waves SoundGrid가 같은 구조(인터페이스는 I/O만, DSP 서버가
채널·버스 처리)로 1GbE에서 64+채널을 상용 운영한다. 우리는 스트립 오프로드로 트랙별
블록 왕복을 이미 운영 중이므로(실측 왕복 0.6–0.8 ms, ping 0.36 ms), 남은 것은 노드가
개별 트랙을 **돌려주는** 대신 **모아 합산해 믹스를 돌려주는** 것이다.

## 역할 분담 — 이 선이 설계의 core

**맥이 갖는 것 (편집 의미론 전부):**
- 클립 재생(디스크 스트리밍), 서드파티 VST3, 라이브 입력 모니터
- **볼륨·팬·자동화를 전송 전에 선적용** — 자동화는 프레임 단위 커브라 노드로 보내면
  상태 동기가 지옥이 된다. 맥이 pre-fader 신호에 다 구워서 보내면 노드의 일은
  "DSP + 합산"으로 순수해진다. 편집이 소리를 바꾸는 경로가 맥 안에만 있다는 뜻이고,
  이것이 재현성과 디버깅 가능성을 지킨다.

**노드가 갖는 것 (순수 DSP):**
- 트랙별 콘솔 스트립 (지금도 함)
- 버스 라우팅 합산 (맥이 보낸 라우팅 테이블대로)
- 버스/Aux 인서트 체인 (누라쿠스트 모듈)
- 마스터 인서트 체인 + 마스터 합산
- 반환: 마스터 스테레오 1개 (+ 버스 미터/GR 텔레메트리)

## 대역폭·지연 예산

- 64트랙 × 187.5블록/s × 256프레임 × 2ch × 4B ≈ 24 MB/s ≈ 200 Mbps — 1GbE에서 여유,
  SoundGrid와 같은 급. 100트랙이어도 38 MB/s로 수용 가능.
- 블록 주기 5.3 ms(256@48k) 안에 왕복해야 함. 단일 세션 0.6–0.8 ms 실측이므로
  **채널 배칭이 관건**: 트랙마다 패킷 하나면 64트랙 = 64왕복이 아니라, 한 UDP
  datagram에 여러 트랙 블록을 실어(≤ ~1400B MTU 조각) 왕복 수를 O(트랙/6) 수준으로.

## 프로토콜 확장 (NART v2 — 기존과 공존)

- `NA_RT_MIX_CFG` (제어): 믹서 그래프 스냅샷 — 트랙 목록(id, 출력 버스), 버스 목록과
  인서트 체인(모듈 id + 파라미터), 마스터 체인. 변경 시에만 재전송(시그니처 비교).
- `NA_RT_MIX_BLK` (데이터): 시퀀스 번호 + 트랙 id + 선적용된 pre-fader 256프레임.
  여러 트랙을 한 datagram에 배칭.
- `NA_RT_MIX_OUT` (반환): 같은 시퀀스의 마스터 스테레오 + 버스 피크/GR 요약.
- 미스 처리: 라이브는 그 블록만 로컬 mixTimelineFrame 폴백(모니터가 끊기지 않게),
  **엄격 바운스는 폐기** — 기존 원칙 그대로.

## 검증 게이트 (구현 전에 정해 둠)

1. **패리티**: 엄격 원격 바운스를 노드 믹서 경로로 돌려 로컬 mixTimelineFrame 결과와
   샘플 비교 — 콘솔 패리티와 같은 기준(리눅스/맥 libm 바닥 ≈ −70 dB)을 넘으면 실패.
   합산은 부동소수 덧셈 순서까지 맞춰야 하므로 **트랙 정렬 순서를 프로토콜에 명시**.
2. **드롭 아웃 예산**: 재생 10분 동안 폴백 블록 수를 세어 0.1% 미만.
3. **부하**: 노드 4코어에서 64트랙 스트립+버스 처리 여유율 측정.

## 단계

- **M1**: 프로토콜 배칭 + 노드 합산 세션(스트립→플랫 합산→마스터 체인). 버스 없이
  "전 트랙 → 마스터" 먼저. 패리티 게이트 통과가 완료 조건.
- **M2**: 버스/Aux 라우팅 + 버스 인서트 서버측 실행. 역할 표의 **믹서·버스 행이
  여기서 청록**이 된다.
- **M3**: 텔레메트리(버스 미터·GR)를 독/믹서 UI로.
- (별개) 재생·녹음 NDS는 욕심+가능성 확인용 — 미디어 미러링 + 선렌더 파이프라인이
  전제라 이 트랙과 독립적으로 진행. 서드파티 VST3의 리눅스 불가는 전제 사실.

## 전제 조건

- 노드 root 배포(다중 모듈 엔진이 20000 정식 포트로) — 배포 후 `192.168.0.198`로 복귀.
- rt-engine에 NA_RT_MIX_* 핸들러 추가는 기존 `--module` 구조 위에 얹는다.
